## 요청 1. 콘텐츠 섹션 생성기 (`tools/make_content_pages.py`)

작성 세션이 쓴 마크다운 원고를 정적 페이지로 만든다. 손으로 고치는 출력물은 없다. 모든 문구는 생성기가 찍는다.

### 입력: `content/<섹션>/<slug>.md`

섹션은 넷이다: `city`(도시 입주물량), `gtx`(GTX 역세권), `danji`(재건축·리모델링 단지), `column`(해설·반박 근거). 시세는 기존 `/weekly/`·`/monthly/`를 쓴다.

프런트매터(필수 항목은 생성기가 검사하고 빠지면 실패한다):

```yaml
---
title: 2027년 인천 아파트 입주물량, 전세 59주 오름세가 시험대에 섭니다
summary: 인천의 2027년 입주 물량은 ○○세대로 적정 입주량의 ○○%다. 전세는 59주 연속 올랐다.   # 40~60자, 첫 문단 답변 블록
date: 2026-10-25            # 작성일
updated: 2026-10-25         # 최종 갱신일(갱신 때 바꾼다)
section: city
region: 인천                # 선택. 시도·시군구 코드와 연결할 때 쓴다
sources:                    # 숫자의 출처. 기관명과 자료명만, 링크는 공식 페이지
  - 국토교통부 주택건설실적통계(인허가·착공·준공)
  - 한국부동산원 주간 아파트가격동향(2026-10-19 조사)
faq:                        # 선택. 2~4개. FAQPage 구조화 데이터로 나간다
  - q: 2027년 인천 입주 물량은 얼마나 되나요
    a: ○○세대로 한 해 적정 입주량의 ○○%입니다.
---
```

본문은 마크다운이다. 표는 그대로 쓰고, 사이트 데이터에서 가져올 표는 `{{table:moveins:인천:2027}}` 같은 자리표로 적어 생성기가 `data-*.json`에서 채운다(숫자를 손으로 적지 않는다는 데이터 원칙). 이미지는 `content/<섹션>/img/` 아래에 두고 상대 경로로 쓴다.

### 출력: `/<섹션>/<slug>/index.html`

페이지마다 다음을 생성기가 넣는다.

- 제목, `summary`를 첫 문단으로(AI 답변 블록), 작성일·최종 갱신일, 저자(아공맵 운영팀, `/about/` 링크).
- 본문, 표, 출처 목록(프런트매터 `sources`), 면책 한 줄(투자자문 아님).
- 구조화 데이터 JSON-LD: `Article`(headline, datePublished, dateModified, author=Organization 아공맵, publisher), `FAQPage`(faq가 있을 때), 표가 원천 데이터일 때 `Dataset` 또는 `Table`(선택).
- OG 카드: 기존 `make_og_cards.py` 방식으로 1200×630 하나.
- 같은 섹션 안의 이전·다음 글, 관련 시도 리포트(`/zone/<시도>/`) 링크.
- 기존 페이지와 같은 머리(`app.css`, 랜드마크, 건너뛰기 링크, 글자 크기 하한 11px) 규칙을 따른다.

섹션 목록 페이지 `/<섹션>/index.html`(최신순, 요약 한 줄)과 홈의 "최근 리포트" 묶음(최근 6편)도 만든다.

### 배치와 시험

- `update-cloud.yml`의 생성기 다섯 개 뒤에 이 생성기를 붙인다. 원고가 없으면 아무것도 바꾸지 않고 0으로 끝난다.
- `make_feed.py`, `make_llms_txt.py`, `sitemap.xml` 생성에 새 섹션을 넣는다. llms.txt에는 섹션별 최신 10편을 제목과 요약으로 싣는다.
- 시험(`tools/tests/test_content_pages.py`): ① 프런트매터 필수 항목이 빠지면 실패한다. ② 자리표 표의 숫자가 `data-*.json`과 같다. ③ JSON-LD가 유효한 JSON이고 dateModified가 `updated`와 같다. ④ 사이트맵과 llms.txt에 새 글이 들어간다. 각 시험의 독스트링에 "무엇을 바꾸면 빨개지는지"와 "픽스처가 어떤 상태를 재현하는지"를 적는다(저장소 CLAUDE.md 규칙).

## 요청 2. AI 검색·검색엔진 기술 항목

1. `robots.txt`: 지금은 전체 허용이다. 그대로 두되, GPTBot·ChatGPT-User·PerplexityBot·ClaudeBot·Google-Extended·Bingbot을 명시적으로 허용하는 줄을 넣고 CCBot(학습 전용)만 막을지는 대표 결정으로 남긴다. 기본은 전부 허용이다.
2. `sitemap.xml`에 `lastmod`를 넣고, 새 섹션 페이지를 포함한다.
3. 구글 서치콘솔과 빙 웹마스터에 사이트를 등록하고 사이트맵을 제출한다. 네이버 서치어드바이저에도 새 섹션의 사이트맵을 제출한다. 등록은 대표 계정이 필요하므로, 개발 세션은 필요한 메타 태그와 절차를 docs에 적어 대표에게 넘긴다.
4. 홈과 시도 리포트 페이지에 `dateModified`를 JSON-LD와 화면에 함께 표시한다(지금은 데이터 기준일만 있다).
5. `llms.txt` 옆에 `llms-full.txt`(섹션별 최신 글 전문 마크다운)를 만든다. 생성기가 찍는다.

## 요청 3. 측정

- 데이터 세션이 매달 1일에 주요 질문 20개(예: "2027년 인천 아파트 입주물량", "GTX-A 동탄역 아파트", "분당 아름마을 재건축")를 네이버 AI 브리핑, 구글, ChatGPT, Perplexity에서 돌려 아공맵이 인용되는지 기록한다. 같은 질문을 3회 돌려 비율로 적는다. 기준선은 11/1에 잰다.
- GA에서 `chatgpt.com`, `perplexity.ai`, `copilot.microsoft.com`, `gemini.google.com` 유입을 월간 보고에 넣는다.
