# 로컬 전용 작업 목록 (2026-09-23 개설)

클라우드 세션(Claude Code on the web)은 저장소만 새로 받은 컨테이너에서 돈다. API 키, gitignore 대상
폴더(`drafts/`, `logs/`), Windows 브라우저, 작업 스케줄러가 없다. 아래 항목은 **로컬 세션에서만** 할 수 있으므로
로컬 세션이 이 문서를 보고 관리한다. 코드 수정·시험·문서·생성기 개선은 클라우드 세션에서 한다.

항목을 집거나 끝낼 때는 백로그와 같은 방식으로 세션명·시각·커밋 해시를 적는다.

## 역할 나눔

| 작업 | 클라우드 세션 | 로컬 세션 |
|---|---|---|
| 코드·생성기·시험 수정, 커밋·PR | ✅ | 가능(필요할 때) |
| `pytest` 검증 | ✅ (SessionStart 훅이 `pytest`·`pillow` 설치) | ✅ |
| 데이터 갱신 | ✖ 돌리지 않음. GitHub Actions `update-cloud.yml`이 담당 | ✖ 로컬 러너 휴면(아래 4번) |
| 블로그 초안 생성·발행 | ✖ | ✅ |
| 네이버 검색 색인·순위 확인 | ✖ | ✅ |

## 항목

| # | 항목 | 왜 로컬인가 | 상태 |
|---|---|---|---|
| 1 | 블로그 초안 생성: `make_naver_post.py`, `make_theory_post.py <편번호>` → `drafts/` | 산출물 `drafts/`가 gitignore라 클라우드에서 만들면 사라진다. 캡처에 로컬 Chrome/Edge 경로를 쓴다 | 상시 |
| 2 | 해석 문단 작성 후 네이버 블로그 검토·발행(화: 지역·사이클 격주, 금: 주간 시세) | 사람이 검토하고 발행한다. `write-reminder.yml` 이슈가 알림, `publish-check.yml`이 닫는다 | 상시 |
| 3 | `naver_serp.py --index`, `--track` 색인·순위 확인 | `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`가 로컬 환경 변수에만 있다. 이력 `tools/serp-history.jsonl`도 gitignore | 상시 |
| 4 | 로컬 러너 `run_weekly_update.bat` 재가동 여부 | Windows 작업 스케줄러 항목. 대표 결정 대기(백로그 22). 켜면 `test_batch_parity`로 클라우드와 순서·대상이 같은지 확인 | 결정 대기 |
| 5 | 배치 로그 `logs/` 확인 | gitignore. 로컬 러너를 켰을 때만 의미가 있다 | 4번에 딸림 |
| 6 | 키가 필요한 1회성 조회·시딩(`update_adv_data.py --discover`, `--seed-*`, `--heal-*`) | `KOSIS_API_KEY` 등 키가 로컬에만 있다. 결과를 커밋하기 전 pytest를 돌린다 | 필요할 때 |

## 로컬에서 커밋할 때

- CLAUDE.md "여러 세션이 같은 저장소를 쓴다" 규칙을 그대로 따른다(`git add`와 `git commit`을 한 명령으로,
  `git add -A`·`git stash` 금지, 푸시 전 `git fetch`).
- 클라우드 세션이 같은 `main`에 커밋하므로 로컬 작업을 시작하기 전에 `git pull`로 먼저 맞춘다.
