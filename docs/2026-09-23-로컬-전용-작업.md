# 로컬 전용 작업 목록 (2026-09-23 개설)

클라우드 세션(Claude Code on the web)은 저장소만 새로 받은 컨테이너에서 돈다. API 키, gitignore 대상
폴더(`drafts/`, `logs/`), Windows 브라우저, 작업 스케줄러가 없다. 아래 항목은 **로컬 세션에서만** 할 수 있으므로
로컬 세션이 이 문서를 보고 관리한다. 코드 수정·시험·문서·생성기 개선은 클라우드 세션에서 한다.

항목을 집거나 끝낼 때는 백로그와 같은 방식으로 세션명·시각·커밋 해시를 적는다.

## GA 로 확인할 질문 (9번, 백로그 28 에서 옮김)

[디자인 오딧](archive/2026-09-18-디자인오딧-UX점검.md)이 답하지 못한 것이다. 이벤트 이름은 개인정보처리방침의 전송 목록(`#ga-events`)과 같다.
화면별로 보려면 '페이지 제목'(view_home·view_stats·view_test) 측정기준을 쓴다(기본 '페이지 경로'는 홈 화면들을 '/' 한 줄로 합친다).

1. **기기 비율** — 보고서 > 사용자 > 기술 > 개요의 '기기 카테고리'. 데스크톱이 몇 % 인가 → 데스크톱 화면(디자인 오딧 7번)을 할지.
2. **`/weekly/` 다음 페이지·이탈** — 탐색 > 경로 탐색, 시작점 `/weekly/`. 이탈률과 `blog_link`·`nav_tab` 클릭 → '더 둘러보기'가 너무 아래인지.
3. **`/cycle/` 스크롤·요약 이동** — `scroll` 이벤트(향상된 측정의 스크롤이 켜져 있으면 90% 도달)와 `tldr_jump`·`cycle_jump` 수를 `/cycle/` page_view 와 견준다 → 목차·진행 막대(디자인 오딧 8번)의 효과 크기.
4. **퀴즈 이탈 지점** — `quiz_start` 대비 `quiz_complete`, `quiz_answer`의 `idx`별 수(맞춤 측정기준으로 `idx` 등록이 필요할 수 있다) → 어느 문항에서 떠나는지.
5. **시세 탭 보기 전환** — `stats_gt`(지도·그래프·표)·`market_tab`·`adv_tab`·`trend_pick` 비율 → 어느 보기가 쓰이는지.

## 로컬 러너를 다시 켤 때 먼저 정리할 차이 (2026-09-23 전체 점검)

클라우드 배치(`update-cloud.yml`)와 비교해 `run_weekly_update.bat`에 남은 차이다. `test_batch_parity`는
생성기 순서·대상만 비교하므로 아래는 잡지 못한다.

- `git diff --quiet`는 추적되지 않은 새 파일을 보지 못한다. 새 파일만 생긴 회차는 커밋하지 않는다(클라우드는 `git add` 뒤 `diff --cached`).
- `make_weekly_share` 실패 시 로컬은 전체 중단, 클라우드는 ⚠️를 남기고 커밋한다. 안전 동작이 반대다.
- 푸시 전에 pull 을 하지 않는다.
- 실패하면 `git restore`로 cycle·share·weekly 등을 되돌리는데, 공유 작업 트리에서 다른 작업의 손 수정까지 지운다.

## 로컬에서 커밋할 때

- CLAUDE.md "세션 운영"의 공통·로컬 세션 규칙을 그대로 따른다(`git add`와 `git commit`을 한 명령으로,
  `git add -A`·`git stash` 금지, 푸시 전 `git fetch`).
- 클라우드 세션의 PR 병합과 `stats-bot` 배치가 `main`을 계속 바꾸므로 로컬 작업을 시작하기 전에 `git pull`로 먼저 맞춘다.
