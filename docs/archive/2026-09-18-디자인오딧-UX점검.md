# 전 페이지 디자인 오딧 · UX 점검 (2026-09-18, 리뷰 세션)

라이브 사이트(sw v153) 전 페이지를 375px 와 1280px 에서 **실측**했다. 사이트맵 32개 주소 + 홈의 해시 화면
5개(통계 3종·퀴즈 선택·문항) + 공유 페이지 + 404.

## 방법과 한계

- 같은 출처 iframe 에 각 페이지를 폭 375·1280 으로 띄워 렌더된 DOM 을 쟀다: 가로 넘침, 제목 줄 수, 누르는
  대상의 크기, 글자 크기 분포, 명도 대비(반투명 배경은 합성해서 계산), 렌더된 웨이트·자간·radius·폰트,
  메타 정보. 걸린 항목은 실제 375px 뷰포트에서 원인(클래스·색·여백)까지 다시 확인했다.
- 정적 감사(`tools/audit_design.py`)는 전 페이지 "위반 없음"이다. 아래는 전부 **렌더해야 보이는 것**이다.
- ⚠️ **눈으로 본 것이 아니다.** 이 세션의 브라우저 창이 화면에 그려지지 않아 스크린샷이 빈 이미지로 나왔다.
  비례·여백의 인상, 색의 조화, 차트의 가독성 같은 시각 판단은 이 문서에 없다.
- ⚠️ **사용자 조사가 아니다.** GA 데이터와 실제 사용자 관찰 없이 한 휴리스틱 점검이다. 맨 아래에 GA 로
  확인할 질문을 적었다.

## 결론

뼈대는 튼튼하다. 가로 넘침이 두 폭 모두 **0건**, 렌더된 800 웨이트 0건, 양수 자간 위반 0건, alt 없는 이미지
0건, 전 페이지에 h1 하나·canonical·설명문이 있다. 답을 먼저 주는 구조(주간·시도 리포트)도 첫 화면 안에서
성립한다. 손볼 곳은 세 갈래다: **작은 글자**, **누르기 어려운 대상**, **페이지군마다 다른 조판 치수**.

## 우선순위 낮음

- `/weekly/` 지도 타일: 글자 `#8f2318` on 합성 배경 약 `#e9a19a`, 12px 에서 대비 약 **4.1**. 상승 폭이 큰 칸일수록 낮아진다. 글자를 `--ink`로 두고 색은 바탕만 맡기면 해결된다. 시도 리포트 분기표의 빨간 칸도 4.40~4.48 로 경계선이다.
- 통계 "매매 기준" 보조 글자 `rgb(121,145,133)` 11px 대비 3.12.
- 404 에 설명문·canonical 없음(검색 대상이 아니라 무해).
- 기본통계 화면에서 Pretendard 가 아닌 글자 요소 24개(차트 범례·축일 가능성, 폰트 로딩 뒤 `update('none')` 경로 확인).

## 잘 되어 있는 것

- **답이 먼저 온다.** `/weekly/`는 첫 화면(812px) 안에 기준일 → 결론 h1("경기 +0.18% 가장 크게 올랐다") → 한 줄
  요약 → 지도가 다 들어온다. 시도 리포트도 h1 → 판정("매우 부족") → 세 줄 분해가 첫 화면이다. 블로그에서
  들어온 사람이 스크롤 없이 답을 얻는다.
- 홈 모드 전환(지도/그래프/표)과 하단 탭바 4개(94×62px)는 누르기 충분하다. 퀴즈 보기 버튼 164×96px.
- 가로 넘침 0, 표는 상자 안에서만 스크롤한다. 2026-08-01 에 잡았던 "차트가 페이지를 가로로 늘림"은 재발하지 않았다.
- 디자인 방향 '원부'의 규칙(웨이트 배급·자간·대문자 금지·Pretendard)이 렌더 결과에서도 지켜진다.

## GA 로 확인할 질문 (이 점검이 답하지 못한 것)

1. 기기 비율: 데스크톱 방문이 몇 % 인가 → 7번을 할지 말지.
2. `/weekly/` 유입의 다음 페이지와 이탈률 → "더 둘러보기"가 너무 아래인지.
3. `/cycle/` 의 스크롤 도달률과 `tldr_jump` 클릭 비율 → 8번의 효과 크기.
4. `quiz_start` 대비 10번 문항 도달률, 문항별 `quiz_answer` 이탈 지점 → 9번과 문항 난이도.
5. 통계 탭에서 지도/그래프/표 전환 사용 비율 → 2번의 체감 크기.
