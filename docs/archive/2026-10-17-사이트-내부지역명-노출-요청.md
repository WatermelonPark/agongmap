# 요청: 사이트 화면의 내부 지역 이름 '전남광주'를 검색 이름 '광주·전남'으로 (백로그 46)

- 요청: 로컬 마케팅 세션, 2026-10-17 (대표 승인 "응 요청서 남겨줘")
- 담당: 개발 세션(생성기·홈 화면)
- 관련: `tools/make_naver_post.py` 의 `SEARCH_NAME = {'세종': '세종시', '전남광주': '광주·전남'}` (블로그 쪽은 이미 이 표기를 쓴다)

## 증상

10-17 부산 지역 편 초안을 넘기기 전에 점검하다가, 블로그에 붙일 사이트 캡처(16개 시도 판정표)에 판정 단위의 내부
이름 '전남광주'가 그대로 찍혀 있는 것을 봤다. 블로그 본문은 2026-10-15에 이미 '광주·전남'으로 고쳤다(75697d33·40e1a670)
그러나 캡처는 사이트 화면이라 생성기에서 고칠 수 없다. 사람들은 이 지역을 '광주·전남'이나 '광주'로 검색한다
(키워드도구 실측). '전남광주'는 검색되지 않는 말이다.

## 지금 보이는 곳 (10-17 main 기준, 화면 글자)

| 화면 | 생성기(추정) | 보이는 자리 |
|---|---|---|
| `/zone/<지역>/` 아래 '다른 지역' 판정표 | `make_sido_pages.py` | 카드 이름 `<b>전남광주</b>` (블로그 지역 편 판정표 캡처에 그대로 실린다) |
| `/moveins/` | `make_indicator_pages.py` | 표 행 이름, 요약 문장 "가장 많은 곳은 전남광주(적정물량의 88%)" |
| `/jeonse-ratio/` | `make_indicator_pages.py` | 표 행 이름 |
| `/monthly/` | `make_monthly_page.py` | 표 행 이름(2곳), "증감이 큰 곳" 링크 글자 |
| `/cycle/` | 사이클 리포트 생성기 | 본문 "전남광주(78%)", 차트 라벨(입주 → 전세 하락 막대, 전세가율 띠, 동조성 등. 블로그 사이클 6편 캡처는 사본에서 바꿔 떴다) |

홈(`index.html`)은 정적 글자에는 없고 지도·표가 데이터에서 이름을 읽으므로 화면에서 따로 확인이 필요하다.

## 요청

화면에 **보이는 이름**만 '광주·전남'으로 바꾼다. 판정 단위 키(`전남광주`), 주소(`/zone/전남광주/`), 데이터 키는 그대로 둔다.
블로그 생성기의 `SEARCH_NAME` 과 같은 표를 쓰거나 `sido_zones` 에 표시 이름 정본을 두고 양쪽이 그것을 읽게 하면, 다음 통합 때
한쪽만 바뀌는 일을 막을 수 있다(CLAUDE.md '같은 대상을 재는 코드가 둘 이상이면 같은 상수').

- `/monthly/` 는 정부 표와 대조하는 화면이라 원천(KOSIS) 행 이름을 일부러 따랐을 수 있다. 그렇다면 그대로 두고 이유를 주석으로 남겨 달라.
- 시험: 생성 페이지의 화면 글자(스크립트·스타일 제외)에 '전남광주'가 0개인지 보는 시험. 원천 대조 화면은 예외 목록으로.

## 블로그 영향

지역 편 판정표 캡처, 사이클 편 차트 캡처에 내부 이름이 실린다. 고쳐지기 전까지는 사이클 캡처처럼 사본에서 바꿔 뜨거나 그대로 둔다.
