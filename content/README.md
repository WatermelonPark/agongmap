# 사이트 콘텐츠 원고 (`content/`)

여기 둔 마크다운이 `/city/`·`/gtx/`·`/danji/`·`/column/` 페이지의 **정본**이다. 페이지(HTML)는 배치가 굽는다 —
출력물을 손으로 고치면 다음 배치가 되돌린다. 생성기는 `tools/make_content_pages.py`.

**2026-11-07 원고 규칙(결론형 제목·카드 숫자·'더 보기' 절 금지·앱 캡처 금지·넓은 표)은 [docs/2026-11-07-콘텐츠-원고-규칙-안내.md](../docs/2026-11-07-콘텐츠-원고-규칙-안내.md) 에 모았다 — 새 글을 올리기 전에 읽는다.**

자리표의 **지금 출력은 이 문서가 정본**이다. 첫 19편을 발행하며 손 숫자를 자리표로 바꾼 경위는
[docs/archive/2026-10-27-원고-자리표-전환-안내.md](../docs/archive/2026-10-27-원고-자리표-전환-안내.md) 에 있다(10-27 시점 기록 — 출력 예시는 낡았다).

## 파일 자리

```
content/<섹션>/<slug>.md      섹션 = city · gtx · danji · column
content/<섹션>/img/*.png      이미지(본문에서 상대 경로로)
```

`slug` 는 영소문자·숫자·붙임표만 쓴다. 그대로 주소가 된다(`/city/incheon-2027-moveins/`).

## 프런트매터

```yaml
---
title: "인천 2027년 입주, 적정물량의 {{v:share:인천:2027}}로 전세가 먼저 눌립니다"   # 결론 한 문장, 45자 이하
summary: 한 문단 요약(40~180자). 검색 설명문·og·RSS·AI 답변에 쓰인다. 화면 글 머리는 아래 3줄 요약이 대신한다.
date: 2026-10-27            # 작성일 — 처음 올린 날. 바꾸지 않는다
updated: 2026-10-27         # 최종 갱신일 — 글을 고칠 때마다 바꾼다
section: city               # 폴더 이름과 같아야 한다
region: 인천                # 선택. 쓰면 그 지역 공급 리포트로 가는 링크가 붙는다(시도 전체 글은 city 를 비우고 이것만)
tldr:                       # 정확히 3줄, 각 60자 이하 — 결론 → 근거 → 전망. 글 머리 '3줄 요약'
  - "2027년 인천 입주는 {{v:moveins:인천:2027}}로 적정물량의 {{v:share:인천:2027}}입니다"
  - "연수구·서구에 몰려 그 두 구 전세가 먼저 눌립니다"
  - "2028년은 2027년의 {{v:ratio:인천:2028:2027}}로 줄어 바닥은 2028년 상반기입니다"
audience: 2027~2028년 인천 전세·매매 시점을 재는 실수요자   # 50자 이하. 글 머리 '이 글이 맞는 분'
key:                        # 독자가 하나만 기억할 숫자. label·value 각 12자 이하(자리표를 채운 뒤에도)
  - label: 2027년 입주 적정 대비
    value: "{{v:share:인천:2027}}"
city:                       # 1~3곳. 홈 시군구 이름표의 이름('성남 분당구'·'남양주'·'수원'). 허브 지역 칩·시세 지도 링크가 된다
  - 인천
topic: moveins              # moveins(내 동네 입주) · first-home(역세권 첫 집) · redevelop(재건축·리모델링) · claim(발언 검증)
sources:                    # 선택이지만 권장. 기관명과 자료명. 항목에 '이름: 값' 꼴(쌍점)을 쓰지 않는다 — 짝으로 읽혀 검사가 막는다
  - 국토교통부 주택건설실적통계(인허가·착공·준공)
faq:                        # 선택. 2~4개. FAQPage 구조화 데이터로 나간다
  - q: 2027년 인천 입주 물량은 얼마나 되나요
    a: 아래 표의 합계와 같습니다.
---
```

필수는 `title`·`summary`·`date`·`updated`·`section` 다섯에 2026-11-05 양식의 `tldr`·`audience`·`key`·`city`·`topic`
다섯을 더한 열이다(시도 전체 글은 `city:` 를 빈 값으로 두고 `region` 을 적는다). 앞 다섯이 빠지거나 형식이 어긋나면 그 글은
**건너뛰고 배치 보고에 경고가 뜬다**(반쯤 만든 페이지를 내보내지 않는다). 뒤 다섯이 통째로 없는 옛 양식 글은 구워지되 카드에
지역 칩·핵심 숫자가 빠지고 글 머리가 결론 상자로 돌아가며, 검사기(`…` 줄)와 발행 기록(⚠️)이 알린다. 있는데 어긋나면(길이·모양)
건너뛴다. 글자 수 상한은 자리표를 채운 뒤에도 지켜야 한다
(`content_md.TITLE_MAX` 45 · `TLDR_MAX` 60 · `AUDIENCE_MAX` 50 · `KEY_MAX` 12).

카드 하나로 글을 고르게 하는 구조다(대표 지시 2026-11-05): 허브 `/reports/` 는 '질문으로 찾기'(topic 넷)와 '지역으로 찾기'(city 칩)로
들어와 결론 카드(지역 칩 + 질문 칩 + title + key)로 글을 고르고, 글 머리는 tldr → audience → key 띠 → 본문이다. 글 끝
'이 지역 더 보기'는 시도 리포트·홈 시세 지도(city 첫 칸)·같은 도시의 입주물량 글로 이어지고, 시도 리포트의 '이 지역 글'은
region 과 city 의 시도 양쪽에 묶인다. `title` 은 앞에 검색어(지역·역·단지), 뒤에 결론이다 — 무엇을 다루는지가 아니라 무엇이
그렇다인지. 본문 첫 줄의 제목 카드 그림(`img/<slug>-thumb.png`)은 생성기가 뺀다(제목이 두 번 보였다).

## 본문에서 쓸 수 있는 것

`## ###` 제목, 문단, `- ` 목록, `1. ` 목록, `> ` 인용, `**굵게**`, `` `코드` ``, `[글](주소)`, `![대체글](이미지)`,
마크다운 표. 원고의 `<태그>` 는 글자 그대로 나간다(스크립트가 실행되지 않는다).

생성기가 화면용으로 바꾸는 것(2026-11-07 디자인 검수 — 원고 글자는 그대로다):

- **혼자 선 그림**(한 문단이 `![대체글](img/…)` 하나)은 그림 밑에 `대체글 · 눌러서 크게 보기` 캡션이 붙고 원본으로 열린다.
  그래서 대체글은 그림 이름으로 쓴다('역 반경 1km 단지 위치'). 휴대폰 단(331px)에서 글자가 읽히지 않는 캡처는 캡션이 있어도
  두 번 눌러야 읽힌다 — 같은 숫자가 HTML 표에 있으면 그림은 빼는 편이 낫다.
- **`※` 로 여는 문단**은 표 밑 기준·읽는 법으로 본다. 110자 이하면 14px 각주 문단, 넘으면 '※ 이 표의 기준과 읽는 법' 접는 칸이 된다.
  긴 방법론은 글 끝 '고른 기준' 절로 보내는 편이 읽기 좋다.
- **열이 다섯 이상인 표**는 휴대폰에서 표 밑에 '옆으로 밀어 N열 모두 보기' 한 줄이 붙는다. 핵심 열(가격·필요 현금)은 둘째 자리에
  두면 밀지 않고 보인다(검사기가 일곱 열을 넘는 원고 표를 `※` 로 알린다).
- 같은 출처 각주가 잇따르면 둘째부터 '출처는 위와 같습니다' 한 줄로 줄고, 그림 숫자 카드 가운데 `key` 와 같은 값은 빠진다.

검사기는 `key.value` 가 제목에 이미 있는 숫자이거나, 같은 섹션 다른 글과 같거나, 소수 둘째 자리('105.95%')면 `※` 로 알린다
(카드에서 가장 큰 글자가 새 정보를 주지 않거나 글끼리 숫자로 갈리지 않는다). 고칠 곳(종료 코드)에는 세지 않는다.

## 숫자는 자리표로 — 손으로 적지 않는다

원고에 숫자를 적으면 그 글은 쓴 날에 멈춘다. 배치는 매일 도는데 글만 옛 숫자를 말하게 된다. 그래서 사이트
데이터에 있는 숫자는 자리표로 적고, 생성기가 매 배치 채운다. **모르는 자리표·없는 지역은 실패다**(빈 표를
내보내지 않는다).

| 자리표 | 나오는 것 |
|---|---|
| `{{table:moveins:인천:2027}}` | 그 해 분기별 입주물량과 합계 |
| `{{table:moveins:인천}}` | 연도별 입주물량(예정 포함) |
| `{{table:supply:인천}}` | 공급 판정 요약(적정물량·앞으로 3년·재고·누적 과부족·판정) |
| `{{table:stats:인허가:인천}}` | 계열 최근 12기간 — 인허가·미분양·전세가율·준공·착공 |
| `{{table:weekly:인천}}` | 최근 8주 매매·전세 변동률 |
| `{{table:weekly:분당구}}` | 시군구도 된다 — 그곳의 최근 8주 변동률(이름이 겹치면 `고양 덕양구` 처럼 구까지). 시 이름은 그 시의 구 전부로 풀린다 — `광주`는 광주광역시의 구들이고 경기 광주시는 이름표 그대로 `경기 광주` |
| `{{table:moveins:부천}}` | 도시(시군구)는 연도별 입주물량. 첫 해와 끝 해 사이에 공개 목록에 입주가 없는 해는 건너뛰지 않고 '입주 예정 없음'으로 자리를 둔다(0 으로 적지 않는다, `content_tables.NO_MOVEIN`) |
| `{{table:moveins:부천:2027}}` | 도시는 그 해 **구별** 입주물량과 합계(시도는 분기별) |
| `{{table:complexes:부천:2027}}` | 그 해 입주 단지 목록 — 입주 예정·단지(구)·세대 세 열(구가 없는 시는 `단지`) |

## 그림

`{{chart:...}}` 은 그 자리에 인라인 SVG 를 그린다(이미지 파일이 아니라서 배치가 페이지를 다시 구울 때
숫자가 따라온다). 숫자 카드·범례·각주·대체 텍스트가 함께 들어간다.

| 자리표 | 나오는 것 |
|---|---|
| `{{chart:moveins:구미}}` | 연도별 입주 물량 막대 + 적정물량 기준선, 위에 숫자 카드 세 칸. 입주가 없는 해는 막대 없이 '없음'으로 자리를 둔다(대체 텍스트는 'N년 입주 예정 없음') |
| `{{chart:moveins:구미:2028}}` | 카드가 가리키는 해를 고른다(기본은 올해 다음 해) |
| | 그림 아래에 `3년 합계(2027~2029년) …세대 · 적정물량 대비 …%` 한 줄이 따라붙는다(자료가 얇은 도시는 그 줄만 빠진다) |
| `{{chart:weekly:구미}}` | 최근 26주 매매·전세 꺾은선(매매 실선·전세 점선, 0선 기준) |

GTX·단지 편은 역이나 단지가 있는 **도시 이름**을 그대로 쓰면 된다. 도시 자료 자리표(입주·적정물량·인구 등)는 **시 이름 하나**(`수원`·`남양주`)만 받는다 — 구 이름(`성남 분당구`)이나 `경기 광주`는 검사가 고칠 곳으로 알린다. 주간 꺾은선은 한 지역만 받으므로,
구가 여럿인 도시는 `{{chart:weekly:부천 소사구}}` 처럼 구까지 적는다.

문장 안에 한 값만 넣을 때는 `{{v:...}}` 로 같은 인자를 쓴다.

- `{{v:moveins:인천:2027}}` → `26,935세대`
- `{{v:supply:인천}}` → `8,033세대 여유(1년 적정물량의 0.3배)`
- `{{v:weekly:인천}}` → `+0.02%`
- `{{v:stats:미분양:인천}}` → 최신 기간 값(전세가율은 수준이라 부호 없이 `52.3%`)
- `{{v:share:평택:2027}}` → `224%` (그 해 물량이 적정물량의 몇 %인가)
- `{{v:share3:청주}}` → `106%` · `{{v:moveins3:청주}}` → `21,859세대` — **3년 합계**(2026-11-05).
  연도를 적지 않는다: 자료의 기준월 다음 해부터 3년을 자리표가 고른다(오늘은 2027~2029년). 해가 바뀌면
  창도 함께 움직이므로 옛 글이 옛 3년을 말하는 일이 없다. 한 달·한 해 몰림 숫자 옆에 이것을 붙이면
  '그래서 3년을 보면 어떤가' 가 글에 들어간다(대표 지시 11-05).
  `{{v:share3:서울}}` 처럼 **시도도 된다**. 시도는 사이트 모델의 '앞으로 3년'(앞으로 12분기 지어질 물량
  ÷ 분기 적정물량 × 12)을 그대로 쓰므로, 홈의 공급 판정과 같은 수가 나온다.
  **분자의 출처가 도시와 다르다**: 도시는 청약홈·부동산원의 입주 예정 목록이고, 시도는 국토교통부 준공
  실적과 착공 추정이다(`v:share` 와 같은 사정이다). 한 글에서 도시와 시도의 3년 합계를 나란히 견줄 때는
  그 차이를 글이 밝힌다.
  창 안의 해 하나라도 아직 공개 목록에 없으면 **기다림**(`…`)으로 떨어진다 — 원고는 올려도 되고,
  분양이 들어온 회차에 저절로 구워진다.
- `{{v:share:서울:2027}}` → `28%` · `{{v:need:서울}}` → `74,800세대` — **시도도 된다**(2026-10-29).
  화면 단위는 둘 다 '세대'다(2026-11-12, 원천 '호'는 `sido_zones.unit_text` 가 바꾼다). 다른 것은 산식이다: 도시는
  인구 ÷ 2.5 × 2%, 시도는 국토교통부 자료로 만든 기준표의 분기 적정물량 × 4 다. 분자도 도시는 입주 예정 목록, 시도는 준공 실적과 착공 추정이다.
  한 글에서 둘을 나란히 견줄 때는 그 차이를 글이 밝힌다. 인구(`v:pop`)와 가장 몰리는 달(`v:peak`)은
  도시 자료에만 있어 시도에서는 쓸 수 없다.
- `{{v:streak:분당구}}` → `84주 연속 상승(10월 19일 조사)` · 전세는 `{{v:streak:분당구:전세}}`
  셈은 `/weekly/` 표와 같다(`weekly_moves.streak`). 연속이 보관 이력의 첫 주까지 닿으면 `156주 이상 연속 하락`처럼 '이상'이 붙는다.
- `{{v:need:부천}}` → `6,030세대` (그 도시의 한 해 적정물량)
- `{{v:asof:weekly}}` → `10/26` (주간 시세 최신 조사일). 출처 줄의 조사일은 이것으로 쓴다 — `sources` 에서도 채워진다.
  `(2026-10-19 조사)`처럼 손으로 적으면 같은 글 그림·표 각주(배치가 최신 주로 고친다)와 시점이 갈린다(2026-10-31).
- `{{v:pop:부천}}` → `753,731명(2026년 9월 주민등록)`
- `{{v:peak:부천}}` → `2032년 3월 1,859세대` · 한 해 안에서 고르려면 `{{v:peak:부천:2027}}`
- `{{v:ratio:의정부:2028:2027}}` → `19%` (앞 연도가 뒤 연도의 몇 % 인가 — '5분의 1로 줄어든다' 같은 문장에 쓴다)
  (단지 이름은 자리표에 없다 — 원천의 이름이 길어 문장에 그대로 넣기 어렵다. 단지는 글이 쓰고 숫자만 받는다.)

**단위는 자리표에 이미 들어 있다.** `{{v:moveins:부천:2027}}` 은 `3,962세대` 로 바뀌므로 뒤에 '세대'를 또
쓰면 '3,962세대세대' 가 된다(2026-10-27 첫 19편에서 44곳이 그랬다). 비율도 `%` 까지 들어 있다.

도시(시군구) 숫자는 `tools/data/city_moveins.json` 에서 온다. 그 파일은 원고의 `region` 과 자리표에 적힌
도시를 읽어 배치가 만든다 — 새 도시를 쓰면 다음 배치에서 자동으로 들어온다(손 목록 없음).

지역 이름은 화면 이름(`광주·전남`)과 내부 키(`전남광주`) 둘 다 받는다.

## 자료에 아직 없는 도시를 쓰는 글

그냥 올리면 된다. 검사기는 그런 자리표를 `…` 로 표시하고 **고칠 곳으로 세지 않는다**(종료 코드 0).
발행 워크플로가 원고의 `region` 을 읽어 그 도시만 받아 넣고, 그 회차나 다음 회차에 페이지가 나온다.
글이 구워지기 전까지는 목록·피드·사이트맵에 실리지 않는다.

```
  …    content/danji/gunpo-yulgok3.md:10  {{v:moveins:군포:2027}} — '군포' 는 아직 도시 자료에 없다
```

이름이 틀렸을 때는 `✗` 로 나온다. 홈의 시군구 이름표에 없는 이름은 기다림이 아니라 오타다.

## 올리기 전에

```bash
python tools/content_check.py          # 전수 검사 — 파일과 줄 번호로 알려 준다(--lenient 는 옛 양식을 고치는 동안만)
python tools/make_content_pages.py     # 통과하면 굽는다
```

원고가 규약을 어기면 여기서 바로 멈추고 이유를 말한다. 통과하면 페이지·섹션 목록·홈 '최근 리포트'·
`sitemap.xml` 이 함께 갱신되고, 이어서 `make_feed.py`·`make_llms_txt.py` 가 피드와 `llms.txt`·`llms-full.txt` 에 싣는다.
배치(클라우드·로컬)는 이 순서를 이미 담고 있다.
